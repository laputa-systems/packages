# XSH m4 — Macro Processor Design

## Motivation

GNU m4 has a large gnulib dependency whose 45+ `.in.h` template system
cannot be driven without running `./configure` (a POSIX sh script).  XSH is
not POSIX sh, so GNU m4 cannot be built in a FROM-scratch Laputa container.

This document describes a clean-room m4 implementation in pure XSH.  It
handles the exact feature set required by bison (for parser generation) and
the Linux kernel build.

---

## Requirements

### Bison skeleton expansion

Bison invokes m4 like this (derived from bison's source, confirmed with 3.8.2):

```
m4 -P -I /usr/share/bison [skeleton-file] [grammar-tmpfile]
```

The `-P` flag prefixes every built-in with `m4_`, so `define` becomes
`m4_define`, `divert` becomes `m4_divert`, etc.  Bison's `data/m4sugar/`
library is then loaded via the skeleton, which redefines many `m4_*` names
with richer behaviour built on seven core `builtin([...])` calls:

```
divert   dumpdef   include   m4wrap
patsubst   sinclude   undivert
```

### Linux kernel (7.0.5) bison grammars

The kernel builds four bison grammars in the `scripts/` host-tool tree.  All
use the default yacc.c skeleton (C output), invoked as:

```
bison -o out.c --defines=out.h -t -l grammar.y
```

| Grammar | Purpose |
|---|---|
| `scripts/kconfig/parser.y` | Kconfig language |
| `scripts/dtc/dtc-parser.y` | Device-tree compiler |
| `scripts/genksyms/parse.y` | Module version symbol parser |
| `drivers/scsi/aic7xxx/aicasm/*.y` | AIC firmware assembler (optional) |

No part of the kernel calls m4 directly.  m4 is only reached through bison.

### Direct m4 calls (other packages)

flex installs `share/aclocal/flex.m4` for autoconf users — m4 is invoked
when those users run `autoreconf`.  That path is outside Laputa's build
system and need not be supported now.

## Algorithm

### Expansion model

m4 uses a **push-down token stream** model:

1. A token is read from the head of the input.
2. If the token is an identifier and it names a defined macro, arguments are
   collected (balanced parens + quote nesting), and the macro is called.
3. The expansion result is **prepended** to the remaining input and re-scanned
   (not appended to output).  This is the key invariant that makes nested
   expansions work.
4. Quoted text (`[...]` by default) is output without quotes and without
   re-expansion.
5. Comments are discarded.
6. All other text is output literally.

The XSH implementation approximates this with a recursive string-based loop
rather than a true push-down stack, which is equivalent for the cases bison
exercises (no infinite self-referential macros at the top level).

### Token types

```
WORD      [A-Za-z_][A-Za-z0-9_]*
OPEN_Q    current open_quote (default "[")
LITERAL   any text not matching WORD or OPEN_Q or comment_start
DNL_COMM  comment_start through end-of-line (discarded)
```

### Argument collection

When a WORD is immediately followed by `(`:

1. Consume the `(`.
2. Collect characters, tracking:
   - paren depth: `(` +1, `)` -1
   - quote depth: open_quote +1, close_quote -1 (when paren depth > 0)
3. At depth 0 `)`: the collected text is split on unquoted `,` → argument list.
4. Each argument is stripped of leading/trailing whitespace then expanded.

When a WORD is not followed by `(`: the macro is called with zero arguments.

### Diversion

Output does not go directly to stdout.  A `Map[Int, Str]` holds diversion
buffers 0–9.  `divert(0)` is the "main" output; `divert(-1)` discards.  At
EOF, buffer 0 is written to stdout.

`m4wrap` text is queued and appended to the remaining input just before EOF
processing.

### State record

```
{
  macros:   Map[Str]   # name → body  ("|builtin:NAME|" for built-ins)
  divs:     Map[Str]   # "0".."9" → accumulated output
  cur_div:  Str        # current diversion index as string
  open_q:   Str        # open quote delimiter
  close_q:  Str        # close quote delimiter
  com_start: Str       # comment start delimiter
  com_end:  Str        # comment end delimiter
  wrap:     Str        # m4wrap queue
  sysval:   Str        # last esyscmd exit code
  file:     Str        # current input filename
  line:     Int        # current input line number
}
```

## Proof plan

### Step 1 — bison on a trivial grammar

Install m4 to `/usr/bin/m4` via the PKGBUILD, then run:

```sh
echo '%token NUMBER
%%
expr: NUMBER ;
%%' > /tmp/tiny.y
bison -o /tmp/tiny.tab.c --defines=/tmp/tiny.tab.h /tmp/tiny.y
```

Expected: `/tmp/tiny.tab.c` and `/tmp/tiny.tab.h` produced, containing a
valid LALR parser.  Absence of m4 errors is the pass condition.

### Step 2 — kernel kconfig grammar

```sh
bison -o parser.tab.c --defines=parser.tab.h -t -l \
      scripts/kconfig/parser.y
```

### Step 3 — all kernel host grammars

Build the kernel with `make scripts` (just the host-tool pass) using our
bison + m4.

## Known limitations / deferred

- `eval()` supports 32-bit integer arithmetic only (sufficient for bison).
- `esyscmd` / `sysval`: implemented via XSH `run.text`.  Any command that
  requires a POSIX shell will fail in a FROM-scratch container where `/usr/bin/sh`
  is XSH, but bison and the kernel do not use these built-ins.
- Regex flavour: GNU m4's `regexp`/`patsubst` use ERE; `bregexp`/`bpatsubst`
  nominally use BRE.  We implement both with ERE (which is a superset of BRE
  for the patterns bison exercises).
- `traceon`/`traceoff`: implemented as a no-op flag (tracing not written to
  stderr) because bison and kernel do not rely on trace output for correctness.
- Diversions beyond 9 are not supported (bison uses 0–10 in some skeletons;
  extend the limit if needed).
